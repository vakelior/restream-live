# restream-live

أدوات للبث المباشر على [Restream](https://restream.io) باستخدام FFmpeg.

## لماذا `-c copy`؟

`-c copy` يعني **نسخ بدون إعادة ترميز** — FFmpeg يقرأ الفيديو ويرسله مباشرة دون أي معالجة، فيصبح **استهلاك المعالج (CPU) شبه صفري**. مثالي للبث الطويل.

> ⚠️ الشرط: `-c copy` يتطلب أن يكون الكوديك H.264 (فيديو) + AAC (صوت) لأن هذين المدعومين في بروتوكول RTMP/FLV. إذا كان الملف VP9/Opus يجب التحويل.

## الاستخدام

### 1) بث فيديو (من YouTube أو ملف محلي)

```bash
# عدّل المتغيرات في أعلى الملف أولاً
bash stream.sh
```

### 2) بث فارغ (شاشة سوداء)

```bash
bash blank-stream.sh
```

## متطلبات

- **ffmpeg** — حمّله من https://ffmpeg.org
- **yt-dlp** — `pip install yt-dlp`

## خيارات الترميز (الترتيب حسب الكفاءة)

| الطريقة | الشرح | الضغط على CPU |
|---|---|---|
| `-c copy` | نسخ بدون ترميز | صفر |
| `h264_nvenc` | ترميز على كرت NVIDIA (GPU) | صفر |
| `h264_qsv` | ترميز على Intel (GPU) | صفر تقريباً |
| `libx264 -preset ultrafast -tune zerolatency` | ترميز برمجيات سريع | منخفض |

## تشغيل تلقائي عبر GitHub Actions

يوجد workflow جاهز في `.github/workflows/stream.yml` يثبّت ffmpeg و yt-dlp تلقائياً ويحمّل الفيديو ويبثه.

> ملاحظة: GitHub Actions يفرض حد زمني (6 ساعات للـ job) ومالتي بث تحتاج عملية مستمرة واقعية؛ استخدمه للاختبار أو البث القصير.

## ملاحظة الأمان

ملف البث يحتوي رابط الـ stream key. لا تشاركه علناً — المستودع خاص.
